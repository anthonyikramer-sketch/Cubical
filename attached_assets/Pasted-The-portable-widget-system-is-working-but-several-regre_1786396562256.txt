The portable-widget system is working, but several regressions and layout problems need to be corrected.

This is a focused widget-system correction pass.

Do NOT redesign Cubical.
Do NOT redesign Sakura.
Do NOT add unrelated features.
Do NOT rebuild existing widgets from scratch.

The main goals are:

1. Restore proper compact Calendar behavior.
2. Allow Clock to become significantly smaller.
3. Make ALL widgets portable, including Clock and future widgets by default.
4. Allow dragged widgets to visibly pass OVER the sidebar during transfer.
5. Correct transported-widget placement inside tabs and tools.
6. Create a structured horizontal portable-widget row on non-Home pages.
7. Make transported Notepad wider and shorter.
8. Standardize transported-widget heights.
9. Preserve Home free-floating behavior.

==================================================
1. RESTORE COMPACT CALENDAR
==================================================

The Calendar has regressed.

It is currently stuck displaying the entire month.

Restore its ability to use the compact single-day state.

The compact Calendar should display approximately:

AUG
10
MONDAY

or equivalent current:

- month
- numbered day
- day of week

The compact Calendar should remain a small widget.

The user must still be able to expand/open it to access the full Calendar/month view.

Do NOT force the full-month Calendar to remain visible at all times.

Preserve Calendar events and existing data.

The Calendar should continue supporting resizing where appropriate.

At smaller sizes:
use the compact day card.

At sufficiently larger sizes:
allow the full Calendar interface.

==================================================
2. CLOCK MUST BE ABLE TO BECOME MUCH SMALLER
==================================================

The Clock currently has too much empty space around its contents and cannot shrink enough.

Fix the Clock's minimum dimensions.

In its smallest normal state, the Clock border should sit very close to the actual:

- time
- AM/PM
- relevant small status icons/indicators

There should only be reasonable internal padding.

Do NOT keep a large empty card around the time.

Conceptually:

current problem:

┌───────────────────────┐
│                       │
│      12:07 PM         │
│                       │
└───────────────────────┘

desired compact state:

┌─────────────┐
│ 12:07 PM    │
└─────────────┘

Keep enough padding that it still looks polished.

The smallest Clock should feel like a compact digital desk clock.

Timer/alarm indicators should fit naturally inside or immediately around this compact state.

Do not remove existing Clock functionality.

==================================================
3. ALL WIDGETS SHOULD BE PORTABLE
==================================================

Clock is currently the only widget that cannot be transferred between main tabs.

Fix this.

Clock should now be portable too.

Current portable widgets therefore include:

- Notepad
- Calendar
- Clock
- Link Shelf
- Decision Maker
- Calculator

More importantly:

PORTABILITY SHOULD BE THE DEFAULT FOR FUTURE WIDGETS.

Do not maintain a manual list where every new widget has to separately be taught how to move between tabs.

In the centralized widget registry/configuration, make widgets portable by default unless a specific widget explicitly opts out.

Conceptually:

portable: true

should be the default behavior.

Only unusual future widgets should require:

portable: false

This means future widgets automatically inherit:

- Home free dragging
- sidebar transfer
- Store/Library/Breakroom placement
- Recall
- global Recall Widgets
- nested-view following
- skin-decoration travel
- persistence

Do not create one-off portability implementations for each widget.

==================================================
4. WIDGETS MUST VISUALLY PASS OVER THE SIDEBAR WHILE DRAGGING
==================================================

There is currently a transfer interaction problem.

When I drag a widget toward the sidebar, the widget itself stops visually at the edge of the sidebar.

I want the widget to visually move OVER the sidebar while I am dragging it.

The cursor and widget should remain visually connected.

During active dragging:

- Render the dragged widget above the sidebar.
- Give the dragged widget a higher temporary z-index than the sidebar.
- Do not clip it at the Home/workspace boundary.
- Do not hide part of it underneath the sidebar.
- Do not stop its visible movement at the content edge.

If I drag Notepad toward Library:

I should be able to see Notepad physically floating over the Library button while my cursor is there.

This should make the transfer interaction feel physical and intuitive.

IMPORTANT:

This is only DURING active drag.

Once released:

If the cursor is over a valid tab:
transfer the widget.

If it is not over a valid tab:
return/nudge the widget into usable space as already specified.

==================================================
7. NON-HOME PORTABLE WIDGETS USE A STRUCTURED WIDGET AREA
==================================================

Transported widgets on Store, Library, and Breakroom should NOT behave like randomly floating Home widgets.

Create a dedicated portable-widget area on these pages.

The structure must ALWAYS be:

PAGE / TOOL TITLE

↓

PORTABLE WIDGET AREA

↓

MAIN PAGE OR TOOL CONTENT

This is extremely important.

The screenshot currently shows Notepad ABOVE the:

"Bulk File Renamer"

title.

That is wrong.

Correct result:

Bulk File Renamer
tool subtitle if present

[ portable widgets ]

Bulk File Renamer interface

Do not put portable widgets:

- above the title
- above breadcrumbs
- above Back controls
- on top of the title
- inside the tool content itself

They belong directly BELOW the title/header block and ABOVE the actual page/tool interface.

==================================================

==================================================

The below-title / above-content placement rule applies consistently to:

- Notepad
- Calendar
- Clock
- Link Shelf

- Calculator
- all future portable widgets

Do not special-case Notepad.

Any transported widget should enter the shared portable-widget area.

==================================================
9. PORTABLE WIDGETS SHOULD FORM ONE HORIZONTAL ROW
==================================================

On Store, Library, Breakroom, and their nested views:

Portable widgets should normally occupy ONE horizontal row.

Example:

Your Library.

[ Notepad ] [ Calculator ] [ Clock ]

File Organizer
Spreadsheet Cleaner
Bulk File Renamer
File Finder

All widgets should stay on a single row whenever they fit.

Do NOT make a separate row for each widget.

Do NOT vertically stack them unless necessary.

==================================================
10. WRAP TO A SECOND ROW ONLY WHEN REQUIRED
==================================================

If there are too many widgets to fit in the available horizontal width:

Allow them to wrap naturally to a second row.

Only create another row if there genuinely is not enough width.

Priority:

1. One row
2. Use available horizontal space
3. Second row only if necessary

Do not create excessive vertical space.

==================================================
11. REORDER PORTABLE WIDGETS LEFT-TO-RIGHT
==================================================

Within the portable-widget area, widgets should NOT freely float vertically.

Instead, allow horizontal drag-and-drop reordering.

Example:

Current:

[ Notepad ] [ Clock ] [ Calculator ]

I drag Calculator between Notepad and Clock.

During dragging:

[ Notepad ] [      ] [ Clock ]
              ↑
       Calculator preview

Nearby widgets should gently make room.

Drop result:

[ Notepad ] [ Calculator ] [ Clock ]

This should feel similar to rearranging cards/items in a horizontal list.

The dragged widget should visibly move.

Other widgets should shift to indicate the insertion position.

==================================================
12. TRANSPORTED WIDGETS ARE AFFIXED TO THEIR ROW
==================================================

Once a widget is on Store, Library, Breakroom, or a nested tool page:

Do NOT allow arbitrary vertical free-floating placement.

Its vertical location belongs to the portable-widget area.

The user may:

- reorder it left/right
- move it to a valid main tab
- Recall it Home

But it should remain inside the portable-widget strip.

This gives non-Home pages a predictable clean layout.

HOME remains the only completely freeform canvas.

==================================================

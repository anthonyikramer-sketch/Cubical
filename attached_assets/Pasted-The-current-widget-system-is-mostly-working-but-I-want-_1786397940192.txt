+ border

+ huge empty region
+ border

==================================================

There is currently an interaction bug:

This is incorrect.

Dragging a widget must NOT count as clicking the widget.

This should be fixed at the SHARED WIDGET INTERACTION LEVEL rather than only patching Calendar.

All current and future interactive widgets should inherit this behavior.

==================================================
8. DISTINGUISH POINTER CLICK FROM POINTER DRAG
==================================================

Implement a small drag threshold.

On pointer/mouse down:

Record the initial pointer position.

Do NOT immediately consider the interaction a drag.

If pointer movement remains below a small threshold and the user releases:

Treat it as a CLICK.

If pointer movement exceeds the threshold:

Treat it as a DRAG.

Once an interaction becomes a drag:

Suppress the click/activation that would normally occur on pointer release.

Conceptually:

pointer down
→ record start position

tiny/no movement
→ pointer up
→ CLICK

movement exceeds threshold
→ DRAG STARTS

pointer up after drag
→ DROP
→ DO NOT CLICK

Use a sensible small threshold so tiny hand movement does not accidentally cancel normal clicks.

Approximately 4–6 CSS pixels is reasonable.
